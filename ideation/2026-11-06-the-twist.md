# 共感は誰に、どれだけ／「お、そう来たか」をどこに置くか

**前の提案（`2026-11-06-journey-and-story.md`）の弱点を先に言う。**

**あれは「認識」しか取れていない。** 「API キーを貼り付けた0.5秒」は
会場のほぼ全員が持っている経験だが、**『わかる』で終わって3秒で消える。**
そして **「星の数ではなく、誰の星か」は、もう知られている考え方**
（web of trust、フォローしている人の輪）。**よくできているが、驚きが無い。**

**驚きの無い共感は、覚えられない。** → §2 で入れ替える。

---

## 1. 共感は、誰に、どれだけ取れるのか

**「多くの人の共感」と一息に言わない。相手ごとに種類も深さも違う。**

| 相手 | 数 | すでに持っている経験 | 取れる反応 | 深さ | 持続 |
|---|---:|---|---|---|---|
| 会場の開発者 | 数百 | 鍵を貼り付けた／更新が怖い | **認識**「わかる」 | 浅い | **3秒** |
| **審査員** | **〜20** | **1日に60個見る。飽きている** | **驚きだけ。共感はほぼ効かない** | — | — |
| **先に試す人**（会場に濃い） | 数十〜百 | **誰にも褒められずに人柱をやってきた** | **承認**「やっと名前がついた」 | **深い** | **残る** |
| あとで動画を見る人 | 広い | — | 浅い | 浅い | — |

### 本命は「先に試す人」

**会場にいるのは、新しいものを最初に入れて、壊れて、直してきた人たち。**
彼らは**ずっと無償で人柱をやってきて、誰からもそう呼ばれたことがない。**

**「あなたがやってきたことには、名前も価値もある」と言われるのは、
認識ではなく承認。** これは3秒では消えない。

**そして審査員は、共感では動かない。驚きだけで動く。** 分けて設計する。

## 1.5 共感の入口は、鍵の置き場所（本人の言葉・2026-11-06）

> **「API キーをついつい預けたくなる、どこにおいたらいいの、、、
> やっぱ放り込んじゃう、っていうのは共感を得ると思う」**

**こちらが書いていた「Enter を押す前の0.5秒」より、こっちが正しい。**
あれは**躊躇して、押す**という話だった。本当はもっと手前に理由がある。

### 置き場所が、無い

| どこに置くか | なぜダメか |
|---|---|
| `.env` | **リポジトリのすぐ横。** `.gitignore` を一度忘れたら終わり |
| 環境変数 | **子プロセスが全部読める。** AI が立てたプロセスも |
| 1Password / Keychain | 安全。**でもエージェントが読めないので、結局コピーして貼る** |
| 設定ファイルに直書き | 一番楽で、一番まずい |
| **道具に預ける** | **唯一、動く** |

> **安全な置き場所は、全部「使えない」。
> 使える置き場所は、全部「安全でない」。
> だから人は、安全でないほうを選ぶ。**

**これは怠慢ではない。** **それしか動かないから、そうしている。**
**会場の全員が、これを今週やっている。**

**責めないこと。** 「気をつけましょう」と言った瞬間に敵になる。
**「それしか無いですよね」と言う。**

### そして、ここで最初の反転が来る

> **置き場所の問題だと思っていた。**
> **置き場所の問題では、なかった。**
>
> どこに置いても、**渡した先が変わったら、同じこと。**
> 問われているのは場所ではなく、
> **渡した先が、昨日と同じものかどうか。**

**「鍵をどこに置くか」は、間違った問い。**
**正しい問いは「渡した先は、まだ渡したときのものか」。**

**ここから §2 につながる。**
**その問いに自分では答えられない。答えられるのは、先に行った人だけ。**

## 1.7 一番速い説明：GitHub の Star（本人の言葉・2026-11-06）

> **「星の数は、GitHub の Star に近い感覚です。
> ただし、1票の重みがちゃんと整頓されている」**

**これが一番速い。** 会場の全員が GitHub の Star を知っていて、
**全員がそれが壊れていることも知っている。** 説明が要らない。

### 一文で言える

> **GitHub の Star です。
> ただし、押すには自分の鍵でそれを使っている必要があって、
> やめたら消えます。**

**これで製品の全部が伝わる。** 以下は、この1文の内訳でしかない。

### 何が違うか

| GitHub の Star | この星 |
|---|---|
| **押すのはタダ** | **自分の鍵で、その版を使っていないと押せない** |
| 一度押したら消えない | **使うのをやめたら消える** |
| 版と無関係 | **版が変わったら、全員ぶん一斉に消える** |
| **数しか見えない**（誰が押したかは実質見ない） | **誰が押したかが本体。数は出さない** |
| **買える**（star farm は実在する） | 一人一つ（World） |
| **ブックマーク**（「あとで見る」で押した人が大量にいる） | **いま中に居る、という事実** |

**GitHub の Star は「見た」の記録。この星は「使っている」の記録。**

### 「1票の重みが整頓されている」とは

**重み = 近さ × 実在 × 現在。**

| | 重い | 軽い |
|---|---|---|
| **近さ** | 知り合いが押した | 知らない人が押した |
| **実在** | 自分の鍵で使っている | 見ただけ |
| **現在** | **いま使っている** | **昔使っていた（＝もう消えている）** |

**GitHub の Star は、この3つを全部1に潰して足し算している。**
**だから 40,000 の Star と 40 の Star を比べられない。**

### 市場の言い方が、これで具体になる

**「43,012 個の MCP サーバーに、GitHub の Star しか無い」。**

**そして、入れるものを選んでいるのは、もう人ではない。**
**Star を数えているのが AI なら、Star を作るのも AI になる。**

## 2. 「お、そう来たか」— 星は、おすすめではなく人質

### 気づいていなかった前提

**レビューの構造的な欠陥は、嘘があることではない。**

> **書いた人は、もう居ない。**
> 価値を受け取り、書き、去った。**残っているリスクはゼロ。**
> **書いた人のリスクが終わったところから、その人の影響力が始まる。**

**これが、すべてのレビューの形。** 星5つも、いいねも、同じ。

### こちらの星

**星は「いいと思う」ではない。
「いま、自分の鍵で、この版を使っている」という、継続中の事実。**

- **使うのをやめたら消える**
- **版が変わったら、全員ぶん一斉に消える**
- **つまり、星が光っているのは、その人がまだ中に居るから**

> **レビューは、書いた人がもう居ない。
> この星は、まだ中に人が居る。**

**おすすめではなく、人質。**
**推薦ではなく、まだ逃げていないという事実。**

### そして、ここが本当の反転

いまの台本では、星が一斉に消える場面を
**「Priya が守られた」**として見せている。**弱い。**

**星が消えたということは、誰かが先に出てきたということ。**

Priya が無事なのは、誰かが彼女より前に立っていて、**その人が先に気づいて、出たから。**
**同じ絵のまま、UI の出来事が人の出来事になる。**

### つまり、この作品は何なのか

**おすすめの仕組みではない。先に行く人のための、安全装備。**

> **誰かが先に行かないと、誰にも分からない。
> だから、先に行った人が無事に帰れる仕組みを作った。**

**3つの丸は「星が本物である証拠」ではない。**
**先に行くことを、生きて帰れる行為にするための装備。**

| | 装備としての役割 |
|---|---|
| **Ledger** | **先に行く人自身の命綱。** AI には引けない |
| **World** | **一人は一人ぶんしか先に行けない。** 偽のカナリアを千羽送れない |
| **0G** | **中の空気を、手紙を読まずに見張る** |
| **星が消える** | **カナリアが出てきた。後ろの全員に、同時に見える** |

**受け取る側（Priya）は、何もしなくても助かる。**
**この作品の本当の顧客は、先に行く人のほう。**

## 4. 言葉（差し替え案）

| 用途 | 言葉 |
|---|---|
| **つかみ（0:00）** | **「その API キー、どこに置きましたか？」**（一拍）**「置き場所、無いですよね」**<br>*"Where did you put that API key?" … "There isn't a good place, is there."* |
| **最初の反転** | **置き場所の問題だと思っていた。置き場所の問題ではなかった。**<br>*You thought it was a question of where. It wasn't.* |
| **一番速い説明** | **GitHub の Star です。ただし、押すには自分の鍵でそれを使っている必要があって、やめたら消えます。**<br>*It's a GitHub star. Except you can only give one while you're running it with your own key — and it goes out when you stop.* |
| **作品の名前** | **星の数ではなく、誰の星か。** / *Not how many stars. Whose.*（そのまま） |
| **「そう来たか」の一行** | **レビューは、書いた人がもう居ない。この星は、まだ中に人が居る。**<br>*A review is written by someone who already left. This star means someone is still inside.* |
| **星が消える場面** | **誰かが、先に出てきた。** / *Someone got out first.* |
| **締め** | **あなたが何もしていない間に、誰かが先に出てきた。**<br>*You did nothing. Someone else got out first.* |
| **思想の一行** | **先に行く人を、無事に帰す。** / *Bring back the ones who go first.* |

**前案の締め「あなたが何もしていない間に、星は消えた」は使わない。**
**「星が消えた」は現象で、「誰かが先に出てきた」は人。** 人のほうを言う。

## 5. 審査員向け（共感ではなく驚きで取る）

審査員には3分で1回だけ、**前提をひっくり返す瞬間**を置く。場所は**星が消えるところ**。

```
（星が一斉に消える）
字幕：「Priya は、何もしていません」
一拍
字幕：「誰かが、先に出てきたからです」
```

**この一拍が、この動画で一番高い場所。**
**機能の説明をしていないのに、設計が全部伝わる唯一の場所。**

**質疑3分で必ず来る問い「誰が金を払うのか」への答えも、ここから出る。**
