TOMOSHIBI — an agent can use your keys without ever holding them

The scope is signed on a device in your hand. How heavy a request is, is decided by a sealed model that reads it so no one else has to. Anything outside the scope stops before it happens, and the stop is recorded. This page is the whole system on one sheet.

2026-11-06Team uniPrize tracks: 0G / World / Ethereum Foundation CROPS

Executive summary

  1. The key never reaches the skill. The skill asks a broker to act. The broker holds a child token and acts on its behalf, inside a scope the human signed on a Ledger device — which key, which destination, which operation, how many times, until when.
  2. Four different refusals, not one. DENIED (you drew the line), STOPPED (no one could decide), NEEDS_PRESS (a human has not pressed yet) and human_denied / proof_expired (a person said no, or nobody was there). Different stops mean different responsibility, so we never collapse them into “failed”.
  3. Stars are a flame, not a score. A star means “I, a verified human, use this version with my own key.” Change the version and every star goes out at once. Reviews never expire; a flame does.

01What happens in one call

Every call passes two gates before the key is used: a scope the human signed, and a weight the sealed model assigned after reading the request.

Askskill calls /use, no key
Scopematched against the signature
Weigh0G reads the body, sealed
Pressonly if irreversible
Actbroker calls the API
Recordappended, root hash on 0G

Figure 1. The three dark steps are the ones that can refuse. Implemented in broker/src/scope.js, weigh.js, tier.js.

Issuing a star is a separate path and the only place a human identity is required: World ID verifies “a person, and the same person” once per version, and nothing else about them.

02Four refusals

“It stopped” is not one event. Each stop names who stopped it, and that is the substance of the design.

Who stopped it

HTTP 403DENIED
You did, in advance. The request falls outside the signed scope.

The attempt and the reason. No default verdict is invented — a fabricated decision would be worse than no decision.

03The map

The boundaries are the product: the key never crosses to the skill, the body never crosses to us, and the identity never crosses to the trail.

04Who knows what

06Limits, and what is next

One trusted point remains, and we name it rather than let the diagram imply otherwise.

  • The broker holds the key. The honest next step is to run the broker itself inside 0G Private Computer. We have not done that.
  • Stars are not on chain yet. They are in an append-only log; the registry is specified, not deployed.
  • Simulated modes exist for development (ZG_OFFLINE, WORLD_OFFLINE). Every record they produce carries simulated: true, and they are off for the demo.
  • Version matching — a star going out when the version changes — is enforced on the read side today, not inside the broker.
