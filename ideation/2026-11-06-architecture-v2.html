AIが見られない場所を手元に持ち、AIには「誰が信頼したか」を持たせる

信頼の薄いAIには鍵が細く短くしか渡らない。範囲外の要求は証拠付きで保証人に跳ね返る。疑わしいだけのものは知らせるだけ。

全体図 — 3つの場所

信頼しない（PC） AIが届かない（手元） 誰でも検証できる（0G） 外部（World / ENS / API）

流れ① 保証する（人 → AI）

World ID を action「vouch」で出すと、アプリの中で固定の仮名になる。実名は誰にも渡らない。仮名は会ったときに交換し、手元に「会った」の記録が残る。

流れ② 使う（正常系）と、1本の系譜

1回の使用で生まれる5つの記録を、同じ要求ハッシュでつなぐ。これがそのまま 0G への提出物（request ID・root hash）になる。

流れ③ 罰する／知らせるの線引き

何を、どこに置くか

手元だけ

元鍵と立会（Ledger）、平文の API キー（Broker）、自分のつながり（端末）

0G に公開

保証（仮名×AI×濃さ）、違反の証拠、系譜の root hash。誰でも数え、検証できる

どこにも置かない

人間の名前・顔。ゼロ知識の証明と仮名だけが動く

ゼロ知識の使いどころ

使用の瞬間の人間証明と、保証人の仮名。どちらも World ID の流用で、新しく作らない

未決・未確認

  • Broker をどの機械で動かすか（PC の外。Ledger だけでは担えない）
  • 仮名と知り合いの対応づけ（会ったときに QR で交換する案。機器を足すアレンジもあり）
  • Ledger の EIP-712 表示で、範囲がどこまで読める形で出るか
  • 子トークンの方式：Ledger で都度署名か、UCAN / Macaroon 型の減衰か
  • World ID の nullifier を action 固定で仮名に使う設計が、IDKit / Agent Pass で成り立つか。会場の Agent Pass は mock proof
  • 重みの式（濃さ3段の点数、違反でどれだけ下げるか）
